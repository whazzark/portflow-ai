# Data Model: Suspend a Truck From Service

**Feature**: `GH-252` | **Date**: 2026-08-25 | **Spec**: [spec.md](./spec.md) | **Research**: [research.md](./research.md)

## Truck lifecycle states

`trucks.status` becomes a three-value domain. The state a truck is in decides, on its own, which
collection lists it and which lifecycle action applies.

| State | Meaning | Listed in | Offered for new operational work | Editable |
|---|---|---|---|---|
| `AVAILABLE` | Selectable for new work | available collection + count | yes | yes |
| `SUSPENDED` | Temporarily out of service, still a live reference | suspended collection + count | no | no (D5) |
| `ARCHIVED` | Administratively retired | archived collection + count | no | no |

### Transitions

```
                    archive (#225)
        AVAILABLE ──────────────────► ARCHIVED
            ▲                             │
            │      reactivate (#226)      │
            └─────────────────────────────┘
            │
            │ suspend  (#252 — this slice)
            ▼
        SUSPENDED
            │
            │ return to service (#253 — NOT in this slice)
            └ ─ ─ ─ ─ ─ ─ ─► AVAILABLE
```

Every transition not drawn is refused:

| From | Action | Outcome |
|---|---|---|
| `AVAILABLE` | suspend | **succeeds** — regardless of planned/active discharge involvement (FR-017) |
| `SUSPENDED` | suspend | refused, `ALREADY_SUSPENDED` (FR-005) |
| `ARCHIVED` | suspend | refused, `ARCHIVED` — reactivate first (FR-006) |
| `SUSPENDED` | archive | refused, `SUSPENDED` — return to service first (D3 item 1) |
| `SUSPENDED` | reactivate | refused, `SUSPENDED` (D3 item 2) |
| `SUSPENDED` | update | refused, suspended read-only (D5) |
| `SUSPENDED` | return to service | **not implemented** — `#253` |

Suspension is currently a one-way door in the product. That is the issue's stated boundary, not an
omission; see the plan's Constitution Check.

## `trucks` table

### Changed column

| Column | Before | After |
|---|---|---|
| `status` | `CHECK (status IN ('AVAILABLE','ARCHIVED'))` | `CHECK (status IN ('AVAILABLE','ARCHIVED','SUSPENDED'))` |

### New columns

| Column | Type | Null | Notes |
|---|---|---|---|
| `suspended_at` | `timestamp` | yes | set on suspension; never cleared by this slice |
| `suspended_by_user_id` | `uuid` | yes | FK → `users.id`, `ON DELETE SET NULL`, matching the archive/reactivate actor columns |
| `suspension_comment` | `text` | yes | trimmed; `null` when absent, empty, or whitespace-only (FR-009) |

### New constraint

`CHECK (status != 'SUSPENDED' OR suspended_at IS NOT NULL)` — the exact mirror of the existing
`status != 'ARCHIVED' OR archived_at IS NOT NULL`.

### Unchanged and deliberately so

- `trucks_registration_unique` on `LOWER(registration)` — a suspended truck keeps its registration
  reserved (FR-012) because the row is still there. No change is needed for that requirement; the
  SQLite rebuild must simply recreate the index (research D2, spike-verified).
- `trucks_status_index` — still the right index; the suspended collection filters on the same column.
- `transport_company_id` — never touched by suspension (FR-011).

## Lifecycle context, held side by side

A truck carries three independent context blocks. Suspension writes only its own, and FR-011 requires
the other two to survive untouched.

| Block | Columns | Written by |
|---|---|---|
| Archive | `archived_at`, `archived_by_user_id`, `archive_comment` | `#225` |
| Reactivation | `reactivated_at`, `reactivated_by_user_id`, `reactivation_comment` | `#226` |
| **Suspension** | `suspended_at`, `suspended_by_user_id`, `suspension_comment` | **this slice** |

A repeated suspend/return cycle replaces the suspension block only. A truck that was archived and
reactivated in the past keeps both of those blocks readable as history after being suspended.

## Model and transformer

- `TRUCK_STATUSES` widens to `['AVAILABLE', 'ARCHIVED', 'SUSPENDED']`; `TruckStatus` follows.
- `Truck` gains `suspendedAt`, `suspendedByUserId`, `suspensionComment`, and a `suspendedBy`
  `belongsTo(User)` relation alongside `archivedBy` and `reactivatedBy`.
- `TruckTransformer` exposes the three new fields plus a `suspendedBy` summary, so the read contract
  is symmetric with the two existing context blocks.
- `database/schema.ts` is regenerated by `node ace migration:run`, not edited.
- Every `findById` / `list` / `listAvailable` query gains `.preload('suspendedBy')` beside the two
  existing preloads.

## Repository contract additions

```
SuspendTruckCommand = { id, suspendedAt, suspendedByUserId, suspensionComment }

SuspendTruckResult  = { kind: 'SUSPENDED'; truck }
                    | { kind: 'ALREADY_SUSPENDED' }
                    | { kind: 'ARCHIVED' }
                    | { kind: 'NOT_FOUND' }

TruckRepository.suspendAvailable(command): Promise<SuspendTruckResult>
```

Existing result types widen so the third state can never be misreported (research D3):

- `ArchiveTruckResult` gains `{ kind: 'SUSPENDED' }`
- `ReactivateTruckResult` gains `{ kind: 'SUSPENDED' }`
- `TruckWriteResult`'s `{ kind: 'ARCHIVED' }` is joined by `{ kind: 'SUSPENDED' }`
- `BulkTruckLifecycleBlocker.reason` gains `'SUSPENDED'`
- `TruckLifecycleRecord.status` widens to the three-value union

## Cross-slice consequence to record

Because `findCompanyIdsWithAvailableTrucks` counts only `AVAILABLE` trucks, a transport company can be
archived while it still provides suspended trucks. That is correct today (research D6), but it means
**Return a Truck to Service (`#253`) must carry the same archived-transport-company gate, and the same
`FOR UPDATE` company lock, that Reactivate a Truck (`#226`) already has.** Without it, `#253` would
produce an available truck under an archived company and break a recorded domain invariant.

## Vocabulary (`CONTEXT.md`)

| Entry | Change |
|---|---|
| **Suspended Truck** | new — a truck temporarily out of service, still a live site reference, excluded from new operational use while its existing discharge, shift, and rotation involvement continues untouched. _Avoid_: broken truck, inactive truck, archived truck |
| **Available Site Reference** | revise — "not archived" is no longer sufficient; a suspended truck is not archived and is not available |
| **Truck** | revise — note the three lifecycle states |
| **Rotation-Eligible Truck** | revise — make explicit that suspension removes eligibility without interrupting an in-progress rotation, and that a continuation may not start a new rotation for a suspended truck (the forward constraint from research D4) |
| **Archived Resource** | revise — distinguish retirement from temporary suspension, so the two are not conflated again |
