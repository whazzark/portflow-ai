# Data Model: Return a Truck to Service

**Feature**: `GH-253` | **Date**: 2026-08-25 | **Spec**: [spec.md](./spec.md) | **Research**: [research.md](./research.md)

## Truck lifecycle states

No state is added. `trucks.status` keeps the three values `#252` established; this slice delivers the
one transition that was missing.

| State | Meaning | Listed in | Offered for new operational work | Editable |
|---|---|---|---|---|
| `AVAILABLE` | Selectable for new work | available collection + count | yes | yes |
| `SUSPENDED` | Temporarily out of service, still a live reference | suspended collection + count | no | no |
| `ARCHIVED` | Administratively retired | archived collection + count | no | no |

### Transitions

```
                    archive (#225)
        AVAILABLE ──────────────────► ARCHIVED
            ▲   │                         │
            │   │   reactivate (#226)     │
            │   └─────────────◄───────────┘
            │   │
            │   │ suspend (#252)
            │   ▼
            │ SUSPENDED
            │   │
            └───┘ return to service (#253 — this slice)
```

Every transition not drawn is refused:

| From | Action | Outcome |
|---|---|---|
| `SUSPENDED` | return to service | **succeeds**, unless the transport company is archived (FR-007) |
| `AVAILABLE` | return to service | refused, `ALREADY_AVAILABLE` (FR-005) |
| `ARCHIVED` | return to service | refused, `ARCHIVED` — reactivate instead (FR-006) |
| `SUSPENDED` | archive / reactivate / update | unchanged from `#252` — all refused |
| `AVAILABLE` (just returned) | archive / suspend / update | behave exactly as for any other available truck (US3-7) |

With this slice the suspended state stops being a one-way door — the boundary `#252`'s plan flagged
for the review gate is closed here.

## `trucks` table

### New columns

| Column | Type | Null | Notes |
|---|---|---|---|
| `returned_to_service_at` | `timestamp` | yes | set on return; never cleared |
| `returned_to_service_by_user_id` | `uuid` | yes | FK → `users.id`, `ON DELETE SET NULL`, matching the three existing actor columns |
| `return_to_service_comment` | `text` | yes | trimmed; `null` when absent, empty, or whitespace-only (FR-010) |

### No constraint changes

- **No status check change** — no new status value (research [D2](./research.md)).
- **No paired `NOT NULL` check.** The `ARCHIVED` and `SUSPENDED` checks exist because those states are
  meaningless without their timestamp. `AVAILABLE` is the default state of every truck ever created,
  so no equivalent obligation exists.
- The delivered `CHECK (status <> 'SUSPENDED' OR suspended_at IS NOT NULL)` is one-directional, so an
  `AVAILABLE` row that still carries its `suspended_at` — which is exactly what a returned truck is —
  is already legal. This is what makes FR-013 free at the schema level.

### Unchanged and deliberately so

- `trucks_registration_unique` on `LOWER(registration)` — the registration was reserved throughout the
  suspension because the row never left, so the return cannot collide (FR-012, US2-6).
- `trucks_status_index`, `transport_company_id` — untouched.

## Lifecycle context, held side by side

A truck now carries **four** independent context blocks. The return writes only its own; FR-012 and
FR-013 require the other three to survive untouched.

| Block | Columns | Written by |
|---|---|---|
| Archive | `archived_at`, `archived_by_user_id`, `archive_comment` | `#225` |
| Reactivation | `reactivated_at`, `reactivated_by_user_id`, `reactivation_comment` | `#226` |
| Suspension | `suspended_at`, `suspended_by_user_id`, `suspension_comment` | `#252` |
| **Return to service** | `returned_to_service_at`, `returned_to_service_by_user_id`, `return_to_service_comment` | **this slice** |

A repeated suspend/return cycle replaces the suspension block and the return block, one cycle at a
time, and never touches the archive or reactivation blocks (US1-7).

The pairing is deliberate and symmetric: `archive ↔ reactivation` reverses a retirement,
`suspension ↔ return to service` reverses an immobilisation. Conflating the two pairs would make a
truck's history unreadable — research [D1](./research.md).

## Model and transformer

- `Truck` gains `returnedToServiceAt`, `returnedToServiceByUserId`, `returnToServiceComment`, and a
  `returnedToServiceBy` `belongsTo(User)` relation beside the three existing actor relations.
- `TRUCK_STATUSES` is **unchanged**.
- `TruckTransformer#toObject` exposes all three fields plus the `returnedToServiceBy` summary.
- `TruckTransformer#toOperationalView` exposes `returnedToServiceAt` and `returnToServiceComment`, and
  withholds the actor — mirroring how it already treats suspension. See research
  [D9](./research.md) for the disclosure asymmetry this inherits.
- `database/schema.ts` is regenerated by `node ace migration:run`, not edited.
- The nine `.preload('archivedBy').preload('reactivatedBy').preload('suspendedBy')` sites in
  `LucidTruckRepository` become one `preloadLifecycleActors(query)` helper that also preloads
  `returnedToServiceBy` — research [D11](./research.md).

## Repository contract additions

```
ReturnTruckToServiceCommand = { id, returnedToServiceAt, returnedToServiceByUserId,
                                returnToServiceComment }

ReturnTruckToServiceResult  = { kind: 'RETURNED'; truck }
                            | { kind: 'ALREADY_AVAILABLE' }
                            | { kind: 'ARCHIVED' }
                            | { kind: 'TRANSPORT_COMPANY_ARCHIVED' }
                            | { kind: 'NOT_FOUND' }

TruckRepository.returnSuspendedToService(command): Promise<ReturnTruckToServiceResult>
```

The result kinds are `ReactivateTruckResult`'s, minus `SUSPENDED` (unreachable — the source state
*is* suspended) and plus `ARCHIVED`. That is not a coincidence: the two transitions guard the same
invariant and differ only in which state they start from.

**No existing result type widens, and no bulk type changes.** `#252` already taught
`findBulkBlockers` and `BulkTruckLifecycleBlocker` about `SUSPENDED`, and this slice introduces no new
status value for them to misclassify — research [D6](./research.md).

## Write path

```
lock truck row (FOR UPDATE)
  ├── not found                       → NOT_FOUND
  ├── status = AVAILABLE              → ALREADY_AVAILABLE
  ├── status = ARCHIVED               → ARCHIVED
  └── lock transport company (FOR UPDATE)
        ├── status ≠ AVAILABLE        → TRANSPORT_COMPANY_ARCHIVED
        └── UPDATE … WHERE id = ? AND status = 'SUSPENDED'
              ├── 0 rows → re-read and classify (SQLite has no FOR UPDATE)
              └── 1 row  → RETURNED
```

The company lock is the load-bearing part, and it is inherited rather than invented: research
[D3](./research.md) records why a plain read would leave a check-then-act window, and why the
opposite lock order used by company archival cannot deadlock against it.

## Entities from the spec, mapped

| Spec entity | Where it lives |
|---|---|
| Truck | `trucks` row; `Truck` model |
| Truck Lifecycle State | `trucks.status` — unchanged, three values |
| Truck Suspension Context | the `#252` columns — **read and preserved**, never written here |
| Truck Return-to-Service Context | the three new columns + `returnedToServiceBy` relation |
| Transport Company | `transport_companies` row — **read under lock**, never written here; gates the return |
| Rotation-Eligible Truck | no model exists yet (research [D7](./research.md)); the rule is recorded in `CONTEXT.md` for the future rotation slice |
| Discharge Truck Assignment | `discharge_truck_assignments` — **read only**, never written; the return leaves every row untouched |
| Authorized Administrator | `users.role ∈ {ORGANIZATION_ADMIN, OPERATIONS_ADMIN}`, `accessStatus = ACTIVE` |
| Operating Site | implicit — single site per ADR 0003 |

## Vocabulary (`CONTEXT.md`)

| Entry | Change |
|---|---|
| **Suspended Truck** | revise — it is no longer true that a suspended truck "must return to service before it can be archived, reactivated, or updated" *with no way to do so*; the return exists, and the entry names it and its transport-company condition |
| **Returned to Service** | new — the reversal of a suspension, distinct from reactivation, which reverses an archival. _Avoid_: reactivated truck, unsuspended truck |
| **Truck** | revise — note that a truck leaves the suspended state only through the return |
| **Rotation-Eligible Truck** | revise — returning a truck to service restores eligibility under the existing rules; a rotation already in progress is unaffected and does not become a second concurrent rotation (the forward constraint from research D7) |
| **Available Site Reference** | revise if needed — a truck can now become available by two distinct routes |
