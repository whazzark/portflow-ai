# Quickstart: Validate Maintaining Transport Company Contact Details

## Prerequisites

- Node.js compatible with the repository toolchain
- PNPM 10.28.1
- Repository dependencies installed with `pnpm install`
- API and web environment files configured from their checked-in examples
- PostgreSQL available for the manual browser flow; automated API tests use in-memory SQLite

## 1. Apply the new columns and prepare the dataset

```bash
pnpm --filter @portflow/api db:fresh
```

This runs the new `1785200000000_add_transport_companies_contact_details` migration and re-seeds the fixtures. Confirm the command succeeds and then confirm the dataset carries every state this feature depends on:

- five seeded companies with a phone number and an email address;
- **Noroît Logistique**, archived, with both contact columns `NULL` — a read-only company registered before this slice;
- **Kernévez Fret**, available, with both contact columns `NULL` — an editable company registered before this slice, used to exercise FR-018's forced-contact-on-next-update rule.

`apps/api/database/schema.ts` and the Tuyau contract under `apps/api/.adonisjs/` are regenerated by the migration run. Do not edit them by hand; commit whatever the generators produce.

Authoritative field rules, the check constraint, and the write boundary are defined in [data-model.md](./data-model.md); request and response shapes are defined in [contracts/http-api.md](./contracts/http-api.md).

## 2. Run focused API verification

```bash
pnpm --filter @portflow/api test unit \
  --files=tests/unit/transport_companies/administration/contact_details.spec.ts
pnpm --filter @portflow/api test integration \
  --files=tests/integration/transport_companies/administration/contact_details.spec.ts
pnpm --filter @portflow/api test unit --files=tests/unit/transport_companies/**
pnpm --filter @portflow/api test integration --files=tests/integration/transport_companies/**
```

Expected outcomes:

- Creating a company with a valid name, phone number, and email address returns `201` with all three recorded.
- Updating an available company with all three returns `200`, and `id`, `status`, `createdAt`, and every archive and reactivation field are unchanged.
- Updating a company that had no contact details recorded succeeds once both are supplied.
- A body omitting `contactPhone`, omitting `contactEmail`, or omitting both is refused with `422` on **both** the create and the update path, and nothing is written.
- A blank or whitespace-only phone number or email address is refused with `422`.
- `+`, `()`, and `12345` are each refused as phone numbers; `+33 2 40 12 34 56`, `02.40.12.34.56`, and `(02) 40-12-34-56` are each accepted.
- `not-an-email` is refused; a 256-character email address is refused; a 255-character one is accepted.
- A 33-character phone number is refused; a 32-character one is accepted.
- Values with surrounding whitespace are stored trimmed.
- A submission carrying an invalid name, an invalid phone number, and an invalid email address reports all three fields in one `422` response.
- Two different companies may record the same phone number and the same email address; neither is refused.
- Updating an archived company is refused with `409 E_TRANSPORT_COMPANY_ARCHIVED`; an unknown id is refused with `404 E_TRANSPORT_COMPANY_NOT_FOUND`; an observer is refused with `403`; an unauthenticated caller is refused with `401`. Each leaves any previously recorded contact untouched.
- A refused update leaves the previously recorded phone number and email address exactly as they were.
- `GET /api/v1/transport-companies` and `GET /api/v1/transport-companies/available` return both fields, populated for migrated companies and `null` for Noroît Logistique, for an observer as well as an administrator.
- Trucks attached to a company keep their association across a contact change.

Then confirm the constraint itself holds, by attempting to persist a company with exactly one of the two values set (through the model, bypassing the validator). The write must be rejected by `transport_companies_contact_details_check`.

## 3. Run focused web verification

```bash
pnpm --dir apps/web exec vitest run src/features/transport-companies
pnpm --dir apps/web exec vitest run src/features/transport-resources src/features/trucks
```

Expected outcomes:

- The create panel shows required phone and email fields alongside the company name, and a submission missing either is blocked before it reaches the API.
- The edit panel is pre-filled with the company's current name, phone number, and email address.
- Opening the edit panel for a company with no contact details recorded shows both fields empty and required.
- A successful save shows a confirmation, returns to the details view, and the directory reflects the change.
- The details panel shows a contact section with both values for a migrated company.
- The details panel shows one explicit "no contact details recorded" message — not two blank fields — for Noroît Logistique.
- An observer can read the contact section and is offered no action to change it.
- The contact section is readable on an archived company.
- A `422` carrying two field errors attaches one message to the phone input and one to the email input.
- After a refusal, correcting the values and resubmitting succeeds without reopening the company.
- Cancelling leaves the company unchanged.
- The delivered consultation tests still pass: lifecycle tabs, counts, search, ordering, details, empty, and retry behavior are unaffected, and search still matches on company name only.
- The trucks feature, which reads companies from the same collection, is unaffected.

## 4. Run repository verification

```bash
pnpm check
pnpm typecheck
pnpm test
```

All commands must pass before the PR is marked ready. Because no Playwright suite is configured, also complete the affected browser flow below.

## 5. Exercise the affected browser flow

```bash
pnpm dev
```

Validate in a desktop viewport and a narrow mobile viewport:

1. Sign in as an operations administrator and open **Site references → Transport resources**.
2. Open **Create transport company**. Confirm the phone and email fields are present and required, submit with each one empty in turn, and confirm each refusal names the right field.
3. Create a company with all three values. Confirm the confirmation appears, the company lands in the Available tab, and its details panel shows the contact section populated.
4. Open an existing available company, choose **Edit company**, and confirm the form is pre-filled with its current name, phone number, and email address.
5. Change only the phone number and save. Confirm the details panel shows the new number, the email address is unchanged, and status, archive or reactivation context, and **Created** are unchanged while **Last updated** has advanced.
6. Change only the name and save. Confirm both contact details are preserved.
7. Submit a malformed phone number and a malformed email address together. Confirm both inputs carry a message and nothing was saved.
8. Correct the values in place and resubmit; confirm it succeeds without reopening the company.
9. Submit values with leading and trailing spaces and confirm the stored values are trimmed.
10. Record the same phone number and email address on a second company and confirm both are accepted.
11. Open **Noroît Logistique** (archived, registered before this feature). Confirm the contact section states explicitly that no contact details are recorded, rather than showing blank fields, and that no update affordance is offered.
12. Open **Kernévez Fret** (available, also registered before this feature with no contact recorded) and choose **Edit company**. Confirm both contact fields are empty and required, attempt to save with only the name changed, and confirm the save is refused until both are supplied. Then supply them and confirm the empty state is replaced by the recorded values.
13. Open **Loire Vrac Transport** (archived, with contact details already recorded). Confirm its contact section is readable and that no update affordance is offered; then request `?companyDetailsMode=edit` for it directly and confirm no form opens.
14. Confirm a truck attached to a company whose contact changed still shows its company, unaffected.
15. Sign in as an observer and confirm every company's contact section is readable, including the archived one and the un-migrated one, with no update or create affordance anywhere.

Finally, repeat the API access check with an unauthenticated session and a non-active user against both the create and the update path; both must be refused before anything is written.
