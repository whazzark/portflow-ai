# Data Model: Invite a Pending User with a Confidential Activation Link

**Feature**: [spec.md](./spec.md) · **Plan**: [plan.md](./plan.md) · **Research**:
[research.md](./research.md)

One new table, no change to `users`. The invitation writes one row in each, in one transaction
(D8).

## `users` — unchanged, written for the first time by this slice

GH-2 delivered every column this feature writes. The invitation is the first code path that fills
them outside the seeder.

| Column | Written by this feature | Value |
|---|---|---|
| `id` | yes | generated by the model's `@beforeCreate` hook |
| `first_name`, `last_name` | yes | trimmed, exactly as submitted (D7) |
| `email` | yes | trimmed, casing preserved; uniqueness is enforced case-insensitively by the existing `users_email_unique` index on `LOWER(email)` |
| `role` | yes | one of `ORGANIZATION_ADMIN`, `OPERATIONS_ADMIN`, `OPERATIONS_LEAD`, `OBSERVER` |
| `access_status` | yes | always `PENDING` (FR-002) |
| `password` | no | stays `NULL` until acceptance (GH-8) — FR-002, and what keeps login refused (GH-3) |
| `invited_at` | yes | the invitation instant (FR-003) |
| `invited_by_user_id` | yes | the inviting organization admin (FR-003) |
| `activated_*`, `cancelled_*`, `deactivated_*`, `reactivated_*` | no | stay `NULL`; recording any of them here would be a lifecycle event this action did not cause (FR-003) |
| `password_renewal_required_at` | no | stays `NULL`; the invitee chooses their first password, which is not a renewal |

## `user_activation_tokens` — new

```text
id           uuid        primary key
user_id      uuid        not null, references users(id) on delete cascade, UNIQUE
hash         string      not null, UNIQUE          -- SHA-256 hex of the issued secret (D2)
expires_at   timestamp   not null                  -- issued_at + 7 days (FR-008)
created_at   timestamp   not null
updated_at   timestamp   not null
```

**Invariants**

- **One live link per user**: the `user_id` unique index is FR-004 enforced by the database. Issuing
  a new link (GH-9, GH-13) replaces the row rather than adding one.
- **The secret is never stored**: only its digest. Nothing in the schema can return the link a second
  time, which is FR-006 by construction rather than by discipline.
- **`hash` is unique**: a collision would let one secret open two invitations; the index makes that
  unrepresentable, and it is also the index GH-8 looks the secret up by.
- **Cascade**: removing a never-activated user (GH-14) takes its link with it; no orphan row can
  outlive its user.
- **Expiry is data, not a job**: an expired row stays until it is replaced or its user is removed.
  Enforcement is a comparison at use time (GH-8), so this slice needs no scheduled cleanup.

**Model**: `apps/api/app/models/user_activation_token.ts`, extending the generated
`UserActivationTokenSchema` from `#database/schema` — the file is regenerated by
`node ace migration:run`, like every other model in the repository. `User` gains
`@hasOne(() => UserActivationToken)` for the slices that will read it; this feature only writes.

## Entity mapping

| Spec entity | Where it lives |
|---|---|
| **User** / **Pending User** | a `users` row with `access_status = 'PENDING'` and no password |
| **User Activation Link** | a `user_activation_tokens` row, plus the secret that exists only in the `201` response |
| **User Access Status Change** (invitation event) | `invited_at` + `invited_by_user_id` on the created row |
| **User Role** | `users.role` |
| **Operating Organization** | implicit — one organization, one site (ADR-0003); no column, no scope filter |

## Write projections

### `InviteUserUseCase` input

```text
firstName: string        -- trimmed, non-blank
lastName:  string        -- trimmed, non-blank
email:     string        -- trimmed, valid email shape
role:      UserRole      -- one of the four
invitedBy: User          -- the authenticated organization admin
```

### `UserRepository.invite` outcome

```text
{ kind: 'CREATED', user: User, activationToken: UserActivationToken }
| { kind: 'DUPLICATE_EMAIL' }
```

A typed outcome, not an exception: the repository owns the write, the use case owns which refusal
the caller sees (D8).

### `ActivationLinkIssuer.issue(user)` result

```text
{ url: string, hash: string, expiresAt: DateTime }
```

`url` is `<WEB_ORIGIN>/activate/<secret>` (D3). Only `hash` and `expiresAt` are persisted; `url` is
returned to the controller and then to the administrator, once.

## Validation rules

Shape is checked by `inviteUserValidator` (VineJS), meaning by the use case (D7).

| Field | Rule | Refusal |
|---|---|---|
| `firstName`, `lastName` | required, non-blank after trim, ≤ 255 | `422` `E_VALIDATION_ERROR`, field-level (FR-015) |
| `email` | required, non-blank, valid email shape, ≤ 255 | `422`, field-level |
| `email` | not already held by any user, in any access status | `409` `E_USER_EMAIL_CONFLICT`, `meta.accessStatus` (FR-012, FR-014) |
| `role` | one of the four `USER_ROLES` | `422`, field-level |
| viewer | active organization admin | `403` (FR-010) |

## State transition

```text
(no user) --invite--> PENDING  [invited_at, invited_by_user_id, one activation token, no password]
```

The only transition this feature produces. Every arrow out of `PENDING` — activation (GH-8),
cancellation (GH-12), removal (GH-14) — belongs to another slice, and none of them is reachable from
here.
