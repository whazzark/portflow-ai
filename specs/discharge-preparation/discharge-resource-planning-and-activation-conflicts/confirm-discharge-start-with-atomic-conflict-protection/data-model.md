# Data Model: Confirm Discharge Start With Conflict Protection and Handling

This slice adds four nullable columns and two partial unique indexes, and no table. It reads the
preparation model persisted by GH-236 and planned by GH-53, GH-54, and GH-55. It writes only the
status and start columns of one discharge and one shift. Decisions are in
[`research.md`](./research.md).

## Schema changes

One migration, `apps/api/database/migrations/1786300000000_add_discharge_start_confirmation.ts`:

| Table | Column or index | Type | Rule |
|---|---|---|---|
| `discharges` | `started_at` | timestamp, nullable | Set once by the start; `null` while planned |
| `discharges` | `started_by_user_id` | uuid, nullable, references `users` `RESTRICT` | The confirming user; `null` for backfilled history |
| `shifts` | `actual_start_at` | timestamp, nullable | Set when the shift becomes active; `null` while planned |
| `shifts` | `started_by_user_id` | uuid, nullable, references `users` `RESTRICT` | The user who started the shift, distinct from its responsible |
| `discharges` | `discharges_active_dock_unique` | partial unique index on `(dock_id) WHERE status = 'ACTIVE'` | One active discharge per dock |
| `shifts` | `shifts_active_per_discharge_unique` | partial unique index on `(discharge_id) WHERE status = 'ACTIVE'` | One active shift per discharge |

**Backfill** (research.md Decision 6):
- A discharge that is not planned gets `started_at` from its earliest shift's `planned_start_at`, or
  its `expected_start_at` when it has no shift.
- An active or completed shift gets `actual_start_at` from its `planned_start_at`.
- Both actors stay `null`.

`down()` drops the indexes, then the columns.

The generated `database/schema.ts` is regenerated by `node ace migration:run`. The seed
(`database/fixtures/discharge_preparation.ts`) sets the same values for its active and closed
scenarios.

## Entities as this slice reads and writes them

### Discharge (`discharges`)

| Field | Read for | Written |
|---|---|---|
| `status` | Must be `PLANNED`, read under `FOR UPDATE` | `PLANNED → ACTIVE` |
| `dock_id` | Dock status and active holder | — |
| `started_at`, `started_by_user_id` | Detail | The confirmation instant and actor |
| `vessel_name` | Holder label in another discharge's problem | — |

**State transition**: `PLANNED → ACTIVE` only through this slice. `ACTIVE → CLOSED` belongs to
discharge closure. A start on an `ACTIVE` or `CLOSED` discharge answers `E_DISCHARGE_NOT_PLANNED`
and writes nothing.

### First shift (`shifts`)

The planned shift of the discharge with the lowest `planned_start_at`, ties broken by `sequence`
(research.md Decision 7).

| Field | Read for | Written |
|---|---|---|
| `status` | Must be `PLANNED` | `PLANNED → ACTIVE` |
| `planned_start_at`, `planned_end_at` | Choosing the shift; review | Never: the planned period is preserved |
| `responsible_user_id` | Eligibility, read under `FOR SHARE` on the user | — |
| `actual_start_at`, `started_by_user_id` | Detail | The confirmation instant and actor |

The discharge's other shifts are neither read for rules nor written.

### Planned rows read under the discharge's lock

| Row | Current when | Used for |
|---|---|---|
| `product_lots` with `customers.status` | always | `NO_PRODUCT_LOT`, `CUSTOMER_ARCHIVED`, `LOT_WITHOUT_WAREHOUSE_DOOR` |
| `warehouse_door_product_lot_assignments` | `effective_to IS NULL` | A lot's current doors; door claims and `WAREHOUSE_DOOR_HELD` |
| `discharge_truck_assignments` | `released_at IS NULL` | Truck claims and `TRUCK_HELD` |
| `shift_trucks` of the first shift | `effective_to IS NULL` | `SHIFT_WITHOUT_TRUCK`, `TRUCK_ARCHIVED` |
| `shift_warehouse_doors` of the first shift | `effective_to IS NULL` | `SHIFT_WITHOUT_WAREHOUSE_DOOR`, `WAREHOUSE_DOOR_ARCHIVED` |
| `shift_weighing_areas` of the first shift | `effective_to IS NULL` | `SHIFT_WITHOUT_WEIGHING_AREA`, `WEIGHING_AREA_ARCHIVED` |

No row among them is written: the pool, assignments, and selections become effective through the
discharge's status, not through new rows (FR-009).

### Other active discharges (holders)

| Holder query | Match |
|---|---|
| Dock | `discharges.dock_id = :dock AND status = 'ACTIVE' AND id <> :discharge` |
| Trucks | `discharge_truck_assignments.truck_id IN (:held) AND released_at IS NULL`, joined to an `ACTIVE` discharge other than this one |
| Doors | `warehouse_door_product_lot_assignments.warehouse_door_id IN (:current) AND effective_to IS NULL`, joined to an `ACTIVE` discharge other than this one |

Each returns `{ resourceId, dischargeId, vesselName }`. `PLANNED` and `CLOSED` holders never
match.

## Usability rules (FR-012)

| Resource of the first shift | Usable when |
|---|---|
| Truck | Selected currently, held by the discharge, and `AVAILABLE` (not `ARCHIVED`, not `SUSPENDED`) |
| Warehouse door | Selected currently, currently assigned to a lot of the discharge, door `AVAILABLE`, and its warehouse `AVAILABLE` |
| Weighing area | Selected currently and `AVAILABLE` |
| Responsible | `accessStatus = 'ACTIVE'` and role in `OPERATIONS_LEAD`, `OPERATIONS_ADMIN`, `ORGANIZATION_ADMIN` (`isEligibleShiftResponsible`) |

## Start problem (API response value, not persisted)

```text
StartProblem {
  family:  INCOMPLETE_PREPARATION | UNAVAILABLE_REFERENCE | INELIGIBLE_RESPONSIBLE | ACTIVE_DISCHARGE_CONFLICT
  code:    see table below
  subject: { type: DISCHARGE | PRODUCT_LOT | SHIFT | USER | DOCK | CUSTOMER | WAREHOUSE_DOOR | WEIGHING_AREA | TRUCK, id }
  context?: { type: PRODUCT_LOT | SHIFT, id }
  holder?:  { dischargeId, vesselName }      // ACTIVE_DISCHARGE_CONFLICT only
}
```

| Code | Raised when | Subject | Context |
|---|---|---|---|
| `NO_PRODUCT_LOT` | The discharge has no lot | discharge | — |
| `NO_PLANNED_SHIFT` | The discharge has no planned shift | discharge | — |
| `LOT_WITHOUT_WAREHOUSE_DOOR` | A lot has no current door assignment | lot | — |
| `SHIFT_WITHOUT_TRUCK` | The first shift has no usable truck | shift | — |
| `SHIFT_WITHOUT_WAREHOUSE_DOOR` | The first shift has no usable door | shift | — |
| `SHIFT_WITHOUT_WEIGHING_AREA` | The first shift has no usable weighing area | shift | — |
| `DOCK_ARCHIVED` | The dock is archived | dock | — |
| `CUSTOMER_ARCHIVED` | A lot's customer is archived | customer | lot |
| `WAREHOUSE_DOOR_ARCHIVED` | A current door of a lot, or of the first shift, or its warehouse, is archived | door | lot or shift |
| `WEIGHING_AREA_ARCHIVED` | A weighing area of the first shift is archived | weighing area | shift |
| `TRUCK_ARCHIVED` | A truck of the first shift is archived | truck | shift |
| `RESPONSIBLE_INELIGIBLE` | The first shift's responsible is not eligible | user | shift |
| `DOCK_HELD` | Another active discharge uses the dock | dock | — |
| `TRUCK_HELD` | Another active discharge holds a truck of the pool | truck | — |
| `WAREHOUSE_DOOR_HELD` | Another active discharge has a current assignment of a current door | door | lot |

**Rules of the list**:
- Every applicable problem is listed. None stops the evaluation of the others.
- An archived door current on a lot and also selected by the first shift is listed once per context.
- Order: family in the table's order, then the order of the subject in the detail (lots by customer
  and product name, doors within a lot, the shift's resources by name), then by id.
- An empty list means the start would be accepted now. The command re-evaluates under lock.
- Without a planned shift, `shiftId` is `null` and no shift problem is raised.

## Invariants after a successful start

- Exactly one discharge row changed: `status = 'ACTIVE'`, and `started_at` and `started_by_user_id`
  set.
- Exactly one shift row changed: the first shift, `status = 'ACTIVE'`, and `actual_start_at` equal
  to the discharge's `started_at`, with its `started_by_user_id` set.
- No pool, assignment, selection, lot, or other shift row changed. No other discharge changed.
- No other active discharge uses the dock, holds a truck of the pool, or has a current assignment of
  a current door of this discharge.
