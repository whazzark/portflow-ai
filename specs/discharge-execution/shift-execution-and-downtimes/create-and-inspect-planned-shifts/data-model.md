# Data Model: Create and Inspect Planned Shifts

**Feature**: `GH-63` | **Plan**: [plan.md](./plan.md) | **Research**: [research.md](./research.md)

This slice adds **no table, column, index, or migration**. It writes rows into the preparation model
persisted by GH-236 and extended by GH-54 and GH-55. It also derives one read-only value, the
readiness gaps, which is never stored.

## Written entities

### Shift (`shifts`)

| Field | Rule in this slice |
|---|---|
| `id` | UUID generated by the web when the add form opens and sent in the body (research Decision 1). A replay with an `id` already in this discharge adds nothing. |
| `discharge_id` | The locked discharge. Its status must be `PLANNED` or `ACTIVE` (FR-004). |
| `sequence` | Position by planned start among every shift of the discharge, after the addition (research Decision 5). Existing shifts whose position changes are renumbered in the same transaction. A started shift is never renumbered. |
| `status` | Always `PLANNED` (FR-005). |
| `planned_start_at` / `planned_end_at` | Required; end strictly after start. Must not overlap another shift of the discharge; touching periods are accepted (FR-007). On an active discharge, the start must be strictly after the start of every `ACTIVE` or `COMPLETED` shift (FR-008). No constraint from `expected_start_at`; past values are accepted (FR-016). |
| `responsible_user_id` | Locked `FOR SHARE`; must satisfy `isEligibleShiftResponsible` (FR-006). |

Database guarantees already in place: `planned_start_at < planned_end_at`, `sequence > 0`, and
`UNIQUE (discharge_id, sequence)`. Overlap and the started-shift rule are enforced under the
discharge's `FOR UPDATE` lock, as every delivered shift rule is.

### Shift Truck Selection (`shift_trucks`), planned discharge only

A row per truck selected at the addition: `shift_id` is the new shift, `effective_from` is now,
and `effective_to` is null. A truck is accepted when a held pool entry of the discharge exists
for it and it is not suspended. Only the added trucks are locked `FOR SHARE`. These are the rules of
`planShiftSelection`.

### Shift Warehouse Door Selection (`shift_warehouse_doors`), planned discharge only

A row per selected door, from now. A door is accepted when it and its warehouse are `AVAILABLE`
under a `FOR SHARE` lock, taken warehouse first, and when a lot of the discharge currently holds it.
These are the rules of `planShiftWarehouseDoorSelection`, applied to an empty current selection.

### Shift Weighing Area Selection (`shift_weighing_areas`), planned discharge only

A row per selected weighing area, from now, accepted when it is `AVAILABLE` under a `FOR SHARE`
lock. These are the rules of `planShiftWeighingAreaSelection`.

On an active discharge, any non-empty resource list refuses the whole addition with
`E_DISCHARGE_NOT_PLANNED` (research Decision 3). No selection row is written there.

## Derived value: Readiness Gaps (per shift, in the discharge detail)

`readinessGaps: ReadinessGap[] | null`

- `null` for a shift whose status is `ACTIVE` or `COMPLETED` (FR-022).
- An array for a `PLANNED` shift, empty when nothing is missing, in this fixed order:

| Code | Present when |
|---|---|
| `NO_USABLE_TRUCK` | No current truck membership of the shift is usable. A truck is usable when a pool entry of the discharge with `released_at IS NULL` exists for it and its status is `AVAILABLE`. |
| `NO_USABLE_WAREHOUSE_DOOR` | No current door membership is usable. A door is usable when the door and its warehouse are `AVAILABLE` and the door has a product lot assignment of the discharge with `effective_to IS NULL`. |
| `NO_USABLE_WEIGHING_AREA` | No current weighing area membership has an `AVAILABLE` weighing area. |
| `RESPONSIBLE_NOT_ELIGIBLE` | `isEligibleShiftResponsible(responsible)` is false. |

A membership is current when its `effective_to IS NULL`. The derivation reads only relations that
`DischargeRepository.findDetail` already preloads, and it is recomputed on every detail read (FR-021).
The responsible's role and access status never cross the wire: the code alone does.

## State and transitions

```text
Discharge PLANNED ──add shift (period, responsible, resources)──▶ + Shift PLANNED
Discharge ACTIVE  ──add shift (period, responsible)─────────────▶ + Shift PLANNED (after every started shift)
Discharge CLOSED  ──add shift──▶ refused E_DISCHARGE_CLOSED
```

The addition never changes the discharge's status, identity, product lots, door assignments, truck
pool, or any other shift's period, responsible, status, or resources. The only exception is the
renumbering of planned shifts' `sequence` (FR-012).

## Refusals

| Situation | Answer | Field / code |
|---|---|---|
| Missing or malformed value | 422 | `plannedStartAt`, `plannedEndAt`, `responsibleUserId`, `id` |
| End not after start | 422 | `plannedEndAt` · `shiftPeriodOrder` |
| Overlap with another shift | 422 | `plannedStartAt` · `shiftOverlap`; the message names the overlapped shift's period |
| Not after every started shift (active discharge) | 422 | `plannedStartAt` · `shiftAfterStartedShifts`; the message names the latest started shift's period |
| Responsible not eligible | 422 | `responsibleUserId` · `eligibleShiftResponsible` |
| Truck refused | 422 | `truckIds.<i>` · existing truck issue rules |
| Door refused | 422 | `warehouseDoorIds.<i>` · `availableWarehouseDoor` or `assignedWarehouseDoor` |
| Weighing area refused | 422 | `weighingAreaIds.<i>` · `availableWeighingArea` |
| Unknown discharge | 404 | `E_DISCHARGE_NOT_FOUND` |
| Closed discharge | 409 | `E_DISCHARGE_CLOSED` (new) |
| Resources sent to an active discharge | 409 | `E_DISCHARGE_NOT_PLANNED` |
| `id` already used by another discharge's shift | 409 | `E_SHIFT_ID_CONFLICT` (new) |
| Not an eligible preparer, or inactive | 403 | Bouncer `DischargePolicy.update` |
| Unauthenticated | 401 | auth middleware |

Every 422 issue is collected before one is thrown, so the form learns every refusal at once
(FR-025), as `CorrectPlannedShiftUseCase` does.
