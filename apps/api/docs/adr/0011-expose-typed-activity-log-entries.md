# Expose typed Activity Log entries

The Activity Log API will expose a discriminated union of structured entries rather than server-formatted business sentences. Every entry shares an envelope containing its identifier, server time, actor, category, action type, and payload schema version, while the producing domain owns an explicit allowlisted action-specific payload; requests, models, exceptions, secrets, and technical data are never serialized wholesale. Creation payloads retain essential created values, modifications retain only changed fields with their previous and new values, transitions retain their states and significant effects, and removals retain only context that would otherwise disappear. Persisted entries remain immutable and the read layer adapts older payload versions to the current DTO so the frontend can provide links and meaningful change presentation without coupling history to one textual representation. If a stored type or version cannot be adapted, the API returns a safe `UNSUPPORTED_ACTIVITY_LOG_ENTRY` variant containing only the common envelope and reports the incident through technical observability instead of exposing raw JSONB or failing the complete timeline.
